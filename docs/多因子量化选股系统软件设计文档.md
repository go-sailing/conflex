## 1. 引言

### 1.1 设计目标

1. 四大引擎（数据代理、因子引擎、模拟持仓、回测引擎）以 Python 包形式提供，**CLI、Python SDK、Web REST API 三个入口共用同一内核**，杜绝多入口结果口径不一致。
2. 数据源、因子、策略、撮合模型四类扩展点全部**插件化**，新增实现不改核心代码。
3. 本地优先、零外部中间件：单个 Python 进程 + 本地文件（Parquet）+ 单文件数据库（SQLite）即可运行；Web 前端构建产物由后端托管。
4. 回测严格防未来函数：通过分层架构与数据访问边界在代码层面约束，而非仅靠约定。

### 1.2 设计约束

| 约束 | 决策 |
| --- | --- |
| 运行环境 | Python 3.10+；单机本地运行；Windows/macOS/Linux |
| 外部依赖 | 仅数据源 API（网络）；不依赖 Redis、消息队列、外部数据库 |
| 数据规模 | 约 5,000 只 A 股 × 约 10 年日线，单机内存 8GB 可完成日线级回测 |
| 性能目标 | 缓存命中下单因子计算 ≤ 数秒；5 年月度调仓回测 ≤ 1 分钟 |
| 安全约束 | Web 默认绑定 127.0.0.1；密钥本地存储、脱敏展示 |

### 1.3 术语

沿用 PRD 附录术语；新增：**Panel（日期×股票二维数据面板）**、**Bar（一根 K 线）**、**Job（异步任务）**、**Adapter（数据源适配器）**、**Repository（仓储，本地数据读写）**。

## 2. 总体设计

### 2.1 逻辑分层与依赖方向

严格分层，依赖只能自上而下，禁止反向依赖与跨层穿透：

```
┌─────────────────────────────────────────────────────────────┐
│ 入口层 entrypoints    cli/  sdk  webapi(FastAPI routers)     │
├─────────────────────────────────────────────────────────────┤
│ 应用层 application    用例编排：更新数据/选股/调仓/回测/Job    │
├─────────────────────────────────────────────────────────────┤
│ 领域层 domain         marketdata / factors / portfolio /     │
│                       backtest（纯领域逻辑，不依赖 IO 框架）  │
├─────────────────────────────────────────────────────────────┤
│ 基础设施层 infra      数据源适配器/Parquet仓储/SQLite/调度/   │
│                       配置/日志/Web Server                   │
└─────────────────────────────────────────────────────────────┘
```

依赖规则：

- `domain` 不 import 任何 IO 实现（requests、fastapi、sqlalchemy、文件路径），只定义抽象端口（Protocol/ABC）。
- `application` 依赖 domain 的抽象端口；具体实现由 infra 在启动时**依赖注入**。
- `entrypoints` 只做参数解析/HTTP 序列化，不写业务逻辑。
- Web 前端为独立工程，仅通过 `/api/v1` 与后端交互。

### 2.2 运行时进程架构

```
                    ┌──────────────────────────────────────┐
                    │          conflex 单进程 (Python)       │
  浏览器 (SPA) ───► │  Uvicorn(ASGI)                        │
                    │   └─ FastAPI App                      │
                    │       ├─ Routers(/api/v1/*)           │
                    │       ├─ Auth 中间件 (JWT)            │
                    │       ├─ SSE 端点 (/jobs/{id}/stream) │
                    │       └─ 静态文件托管 (web/dist)       │
                    │                                      │
  CLI 命令 ───────► │  Application 用例服务（共享内核）       │
                    │   ├─ MarketDataService                │
                    │   ├─ FactorService / SelectionService │
                    │   ├─ PaperTradeService                │
                    │   └─ BacktestService                  │
                    │         │                            │
                    │  JobManager(进程内, 线程池, 持久化)    │
                    │  Scheduler(APScheduler, 盘后定时)      │
                    └──────────┬───────────────┬───────────┘
                               ▼               ▼
                    Parquet 文件目录      SQLite(meta.db)
                               ▼
                    外部数据源 API(Tushare/AKShare/东财/新浪)
```

要点：

- Web 与 CLI 是同一 Python 包的两个入口，import 同一批 application/domain 对象。
- JobManager 同时服务 Web（SSE）与 CLI（终端进度条），是唯一的长任务执行通道。
- 回测为 CPU 密集型，默认在进程池执行；数据更新为 IO 密集型，在线程池执行。

### 4.2 聚合根：模拟账户（portfolio/account.py）

账户聚合内聚资金、持仓与订单不变量，外部不允许直接改字段：

```python
class Account:
    id: int; name: str
    cash: CashBook                 # 现金账（可用/冻结）
    positions: dict[str, Position] # symbol -> Position

    def place_order(self, ...) -> Order:         # 校验资金/可用股数后冻结
```

关键不变量（违反即抛领域异常）：

1. 买入冻结金额 ≤ 可用资金；卖出数量 ≤ 可用（T+1 后）数量。

3. 结算后当日买入数量才转入 `available_qty`。

## 5. 行情数据获取代理详细设计

### 5.1 端口与适配器

领域层只依赖两个抽象（infra 提供实现并注入）：

```python
# domain/marketdata/ports.py
class MarketDataSource(Protocol):
    name: str
    def fetch_daily_bars(self, symbol, start, end, adjust) -> list[RawBar]: ...
    def fetch_adjust_factors(self, symbol, start, end) -> list[AdjustFactor]: ...
    def fetch_instruments(self) -> list[Instrument]: ...
    def fetch_calendar(self) -> list[date]: ...
    def health_check(self) -> bool: ...

class BarRepository(Protocol):          # 本地缓存仓储
    def coverage(self, symbol, freq) -> tuple[date, date] | None: ...
    def read(self, symbol, start, end, adjust) -> pd.DataFrame: ...
    def upsert(self, symbol, df: pd.DataFrame, is_final: bool): ...
```

适配器统一基类负责原始响应 → 标准字段映射、错误归类：

```python
# infra/datasources/base.py
class SourceError(Exception): ...
class SourceAuthError(SourceError): ...       # 不重试，直接换下一个源
class SourceRateLimit(SourceError): ...       # 触发退避/熔断
class SourceEmpty(SourceError): ...
class SourceNetworkError(SourceError): ...    # 可重试

class BaseDataSource:

        """统一列名/代码后缀/时区/单位；映射表由子类声明 COLUMN_MAP"""
```

### 5.2 多源代理（proxy.py）

代理组合多个适配器，是应用层唯一的数据出口：

```python
class MarketDataProxy:
    def __init__(self, sources, repo, breaker_factory, cache_ttl): ...

    def get_daily(self, symbol, start, end, adjust="qfq") -> pd.DataFrame:
        # 1) 封闭区间读本地（见 5.4 三段式裁剪）
        # 2) 缺口段调用 _fetch_with_failover() 增量拉取
        # 3) 实时段（今日未收盘）走短TTL，不写 final
```

故障轮换与重试决策：

| 异常类型 | 同源重试 | 切换下一源 | 熔断计数 |
| --- | --- | --- | --- |
| Network / 5xx / RateLimit | 是（指数退避，2 次） | 是 | 是 |
| Empty / 数据校验失败 | 否 | 是 | 是 |
| AuthError（token 失效） | 否 | 是（本源标记禁用） | 是 |
| 参数错误（4xx 非限频） | 否 | 否（直接失败） | 否 |

### 5.3 熔断器与限频器

- **breaker.py**：每源一个 `CircuitBreaker`，状态 `CLOSED→OPEN→HALF_OPEN`；滑动窗口连续失败 5 次熔断 300s，到期放行 1 次探测，成功则闭合。
- **ratelimit.py**：令牌桶 `RateLimiter(qps, daily_quota)`；日配额耗尽后该源当天直接跳过。
- **请求去重**：`dict[key, Future]` 的 SingleFlight，key = `(source, api, 参数哈希)`，并发同参请求共享结果。

### 5.4 本地缓存：三段式裁剪与封闭判定

`MarketDataProxy.get_daily` 的核心算法：

```
输入 (symbol, [start,end], adjust)
  today = 当前日期； close_done = 当前时刻 >= 收盘时刻(15:00)
  从 TradingCalendar 得到交易日序列 T
  closed_end   = close_done ? today : today-1   # 封闭日边界
  区间拆三段：
    [start, min(end, closed_end)]   → 历史段：必须命中本地，缺口才联网(is_final)
    (closed_end, today]             → 当日段：若存在则按 TTL 走实时源
    > today                         → 拒绝（未来日期）
  历史段查询 cache_meta 覆盖情况：
    完全覆盖 → 直接读 Parquet，零网络
    有缺口   → 仅对缺口区间 failover 拉取 → quality 校验 → upsert + is_final=1
  返回前：读取原始价 Parquet + adjust/复权因子，按需动态计算 qfq/hfq
```

Parquet 存储（storage/parquet_store.py）：

- 路径：`data/market/daily/<symbol>/<year>.parquet`，schema 固定（与 DailyBar 对齐 + `is_final`）。
- 写入：读旧文件 → concat 去重（保留 `trade_date` 最新）→ 按年重写；小批量更新攒批落盘。
- 读取：按年分区裁剪 + 日期过滤；列裁剪只取所需字段。
- 复权：`data/market/adjust/<symbol>.parquet` 存原始因子；复权价 = 原始价 ×（当日因子 / 基准日因子）。

### 5.5 数据质量与隔离

quality.py 为纯函数链 `validate_daily(df) -> list[Issue]`：完整性、OHLC 合法、价格>0、涨跌停阈值（22% 容差）、停牌（volume=0）。

- 任一 error 级问题：整批数据写入 `data/quarantine/<date>/<source>/`，不 upsert 正式缓存，Job 日志告警。
- warning 级（如跳变）：写入但打标记，仪表盘"数据质量"可查。

### 5.6 更新用例（application/market_service.py）

```python
class MarketDataService:
    def update_daily(self, job: Job, symbols=None, start=None, end=None):
        calendar = self.repo.load_calendar()
        targets = symbols or self.repo.all_listed_symbols()
        for i, sym in enumerate(targets):
            gap = self.repo.next_gap(sym, start)          # 从 last_trade_date 增量
            if gap: df = self.proxy.get_daily(sym, *gap)  # 内部完成轮换/落盘
            job.report_progress((i+1)/len(targets), current=sym)
            if job.cancel_event.is_set(): return JobStatus.CANCELLED
```

断点续传：Job 每处理完一只股票即提交 `cache_meta`，中断重跑自然跳过已完成区间。

## 6. 多因子引擎详细设计

### 6.1 Factor 基类与注册器

```python
# domain/factors/base.py
class Factor(ABC):
    name: ClassVar[str]
    deps: ClassVar[tuple[str, ...]] = ("close",)
    params: ClassVar[dict] = {}

    @abstractmethod
    def compute(self, panel: PanelData) -> pd.DataFrame: ...   # 日期×股票

class FactorRegistry:
    _registry: dict[str, type[Factor]]
    @classmethod
    def register(cls, factor_cls): ...        # 同时提供 entry_point 发现
    def create(self, name, **params) -> Factor: ...
    def list(self) -> list[FactorMeta]: ...
```

- 内置因子用 `@FactorRegistry.register` 装饰；自定义因子放 `conflex_factors/` 目录，通过 Python entry point `conflex.factors` 自动发现，无需改源码。
- 因子命名：`<类别>_<指标>_<窗口>`，如 `price_mom_20`、`price_rev_20`、`risk_vol_60`、`liq_amtavg_20`。

### 6.2 计算调度（FactorService）

```python
def compute_factor(self, factor, universe, dates, adjust="qfq") -> pd.DataFrame:
    key = cache_key(factor.name, factor.params, adjust, universe.version)
    if cached := self.factor_cache.get(key, until=dates.stop):
        return cached                      # 增量命中
    panel = self.bar_repo.load_panel(universe, dates, factor.deps)
    values = factor.compute(panel)
    values = self.preprocess_pipeline(values, panel)   # 截面流水线
    self.factor_cache.put(key, values)
    return values
```

- 面板加载使用 `slice_until(t)`，因子在 t 日只能看到 ≤ t 的行情。
- 因子缓存为 Parquet：`data/cache/factors/<name__phash>/<year>.parquet`，phash = 参数+复权+股票池版本哈希。

```python
PIPELINE = [
```

### 6.4 合成、打分与过滤（scoring.py）

```python
def composite_score(frames: dict[str,pd.DataFrame], weights: dict[str,float],
```

## 8. 回测引擎详细设计

### 8.1 事件与时钟（防未来函数的核心）

```python
# backtest/clock.py
class BacktestClock:
    def __init__(self, calendar): self._i = 0
    def now(self) -> pd.Timestamp: return self._dates[self._i]
    def advance(self): ...
    def assert_visible(self, ts): assert ts <= self.now()   # 调试期断言
```

引擎只通过 Clock 暴露"当前日"；数据访问统一经 `PanelData.slice_until(now)`。**禁止向策略传入任何含未来日期的 DataFrame**，并在测试中构造"未来列污染"用例验证。

### 8.2 策略接口与上下文

```python
class Strategy(ABC):
    def on_start(self, ctx: Context): ...
    def on_bar(self, ctx: Context, today: pd.Timestamp): ...
    def on_end(self, ctx: Context): ...

class Context:
    clock: BacktestClock
    factors: FactorAccess          # score(date) 内部强制 date<=today
    broker: Broker
    account: Account
    calendar: TradingCalendar
    def select(...): ...           # 委托给 scoring.select
    def rebalance(self, target): ...# 生成订单进入挂单簿
```

### 8.3 主循环伪代码（engine.py）

```python
def run(cfg: BacktestConfig, strategy) -> BacktestResult:
    ctx = build_context(cfg)                       # 加载股票池/基准/账户/Broker
    strategy.on_start(ctx)
    for today in clock:                            # 单一时间轴
        bar = bar_source.bar_on(today)
        # 1) 撮合"昨日信号单"（T+1 开盘成交）
        broker.match_pending(orders_from_yesterday, bar)
        # 2) 策略只可见 <= today 的数据
        strategy.on_bar(ctx, today)               # 产生今日信号单(挂起)
        # 3) 收盘结算
        account.settle(bar.close)
        equity_curve.append(today, account.total_equity)
        clock.advance()
    strategy.on_end(ctx)
    return assemble_result(equity_curve, trades, cfg)  # 计算指标
```

Point-in-time 股票池：每日 universe = `list_date <= today < delist_date` 的股票集合，退市股保留历史；基准从同一 BarRepository 读取。

### 8.4 绩效计算（metrics.py，纯函数）

输入净值序列、无风险利率、基准净值；输出年化收益/波动、夏普、Sortino、Calmar、最大回撤及持续期、信息比率、胜率、盈亏比、换手率、费用合计；月度收益矩阵供热力图。所有计算有黄金样本单测（已知 3 只股票构造净值，手算对照）。

### 8.5 回测服务与结果

`BacktestService.run()` → 创建 Job（进程池）→ 引擎执行 → 结果写 `backtest_run/backtest_equity/backtest_trade`（含 `data_version`、`params_json`、代码 git hash），前端报告页按 run_id 查询。

## 11. 关键流程时序

### 11.1 行情更新（含轮换/熔断）

```
Scheduler/CLI/Web
  └─MarketDataService.update_daily(Job)
       ├─BarRepo.next_gap(symbol)               # SQLite cache_meta
       ├─MarketDataProxy._fetch(symbol, gap)
       │    for src in sources(order by priority):
       │      breaker[src].allow()? ──no──► continue
       │      ratelimit[src].acquire()
       │      try: raw = src.fetch_daily_bars()
       │      except Retryable: retry(backoff 1/2/4s, max2) ──仍失败
       │             → breaker.record_fail() → 下一源
       │      except Auth: 禁用本源 → 下一源
       │      ok → breaker.record_ok(); break
       │    全部失败 → AllSourcesExhaustedError(聚合原因) → Job失败可续跑
       ├─quality.validate(raw) ─error→ quarantine + 下一源
       ├─ParquetStore.upsert + Repo.update coverage(is_final=1)
       └─Job.report_progress → SSE 推送
```

### 11.2 Web 触发回测

```
浏览器 ─POST /backtests─► Router(鉴权/DTO)
   → BacktestService.run() → JobManager.submit(process pool) → 返回 job_id
浏览器 ─GET /jobs/{id}/stream (SSE)
   进程池: Engine 主循环(逐日 broker.match/strategy.on_bar/settle)
        → 写 backtest_run/equity/trade → Job Succeeded
   SSE: progress... → event:finished
浏览器 ─GET /backtests/{id}/report → ECharts 渲染
```

### 11.3 信号到模拟成交（T+1）

```
T日盘后: ScoreBoard → rebalance 预览 → 用户确认 → order(status=pending, signal_date=T)
T+1开盘后(定时Job): NextDayOpenBroker.submit(order, T+1 bar)
   涨停买单/跌停卖单/停牌 → reject(或顺延)
   可成交 → 滑点定价→CostPolicy计费→trade → account.apply_fill
T+1盘后: settle(收盘价) → account_snapshot → 仪表盘净值更新
```

## 13. 异常、日志与可观测性

### 13.1 异常体系

```
ConflexError
├── DomainError        InvalidOrderTransition/InsufficientCash/InvalidPrice...
├── DataError          SourceError(Auth/RateLimit/Network/Empty)/QualityError/AllSourcesExhausted
├── FactorError        UnknownFactor/WindowInsufficient
├── BacktestError      ConfigInvalid/LeakageError(读到未来数据)
└── InfraError         StorageError/DbError
```

- 全局错误码表（前端按 code 做提示），错误响应携带 `trace_id`。
- LeakageError：引擎/因子中任何访问到 `date > clock.now()` 的数据直接抛错（debug 模式开启严格断言）。

### 13.2 日志

- loguru，统一格式：`time|level|module|trace_id|job_id|msg|fields`；Job 日志额外镜像到 `data/logs/jobs/<id>.log`（环形缓冲 + 文件双写）。
- 数据源轮换强制记录：symbol/区间/失败源/异常类型/耗时/命中源。
- 指标：缓存命中率、各源调用量/成功率/平均延迟、Job 耗时分布（先落日志与统计页，预留 Prometheus exporter）。

## 14. 并发与性能设计

| 场景 | 方案 |
| --- | --- |
| 数据更新 IO 并发 | 线程池（默认 4 线程），每源独立令牌桶；单 Job 内股票级并发，更新类 Job 全局互斥 |
| 回测 CPU 密集 | 进程池（默认 CPU-1，上限 2 个回测），结果通过队列回传 |
| 重复请求合并 | 数据源 SingleFlight；因子计算同 key 去重 |
| SQLite 并发 | WAL + 写操作串行化（应用层单写队列），读多写少无压力 |
| 面板内存控制 | 按字段/年份懒加载；日线全市场面板按 float64 约 5000×2500×N字段，支持按字段裁剪与 float32 降精度开关 |
| Parquet 优化 | 按 symbol/year 分区、snappy 压缩、只读写入列；热点 symbol 进程内 LRU |
| 前端性能 | 图表数据后端预聚合（月度矩阵/IC 序列），K 线按区间请求、ECharts large 模式 |

## 16. 构建、打包与部署

### 16.1 后端

- `pyproject.toml` extras：`conflex[web]`（FastAPI 等）、`conflex[tushare]`（数据源 SDK）。
- 入口点：`[project.scripts] conflex = "conflex.entrypoints.cli:app"`；因子插件 entry point 组 `conflex.factors`。
- 版本化：`__version__` + git short hash 写入回测 `code_version`。

### 16.2 前端与一体分发

1. `cd web && npm run build` → `web/dist`。
2. `scripts/sync_web_dist.sh` 拷贝到 `conflex/resources/web_dist` 并随包发布。
3. 用户侧：`pip install conflex[web]` → `conflex init`（生成配置/建库/建管理员）→ `conflex web start` 打开 `http://127.0.0.1:8899`。
4. 开发模式：后端 `uvicorn --reload` + 前端 `vite dev`（proxy `/api` 到 8899）。

### 16.3 数据目录与升级

- 首次启动自动：建目录 → 执行 schema DDL/迁移 → 空数据引导（先拉交易日历/股票列表）。
- 升级：DB migration 版本号；Parquet schema 演进通过新增列+读取时默认值兼容，不做破坏性改名。

## 17. 编码规范

- Python：ruff（lint+import 排序）、black 行宽 100、mypy 分层检查（domain 层必须全类型标注）；公开接口 docstring（Google 风格）。
- 前端：ESLint + Prettier；组合式 API（`<script setup lang="ts">`）；API 类型由后端 OpenAPI 生成（openapi-typescript），避免手写类型漂移。
- 提交：Conventional Commits；PR 需过 lint + 单测 + golden 回归。
- 禁止事项：domain 层 import IO 库；Router 写 SQL/业务规则；硬编码绝对路径与密钥；回测中使用 `datetime.now()`（只能用 Clock）。
