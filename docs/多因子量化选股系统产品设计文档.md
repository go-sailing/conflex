## 1. 背景与目标

### 1.1 项目背景

个人量化投资者和小型量化研究团队在进行多因子选股研究时，通常面临以下痛点：

1. **行情数据不稳定**：免费/低成本行情源（如 Tushare、AKShare、东方财富、新浪财经等）存在限频、字段缺失、偶发宕机、接口变更等问题，单一数据源无法保证数据获取的连续性。
2. **重复拉取浪费配额与时间**：已经收盘的历史 K 线数据不会再变化，但每次研究仍被重复请求，既浪费 API 积分，又拖慢因子计算。
3. **因子研究链路割裂**：因子计算、选股、模拟交易、回测验证分散在不同脚本或工具中，数据口径不一致，研究结果难以复现。
4. **策略验证成本高**：缺乏统一的回测与模拟持仓框架，难以客观评估因子/策略的有效性。

### 1.2 产品目标

构建一套本地优先（Local-first）的多因子量化选股系统 **Conflex**，实现：

- **数据可靠**：通过多数据源代理与自动故障轮换，保证行情数据"总能取到"；通过本地分层缓存，历史收盘数据"只取一次"。
- **研究高效**：内置多因子分析引擎，支持因子定义、计算、预处理、打分与分层回测。
- **交易可模拟**：提供模拟账户与持仓管理，支持按策略信号进行纸上交易（Paper Trading）。
- **策略可验证**：提供事件驱动回测引擎，准确评估策略在历史区间的收益、风险与换手表现。
- **管理可视化**：提供本地 Web 管理后台，在浏览器中即可完成数据运维、因子研究、选股、模拟交易与回测分析的全流程操作与监控。

### 1.3 非目标（Non-Goals，v1.0）

- 不接入实盘券商交易接口，不下真实订单。
- 不提供高频/Tick 级回测（v1.0 最低粒度为日线，分钟线作为扩展项预留）。
- 不提供 SaaS 多租户服务，v1.0 面向单用户本地部署。
- 不做基本面研报、舆情等另类数据的深度清洗，仅预留数据源扩展接口。

### 1.4 目标用户与典型场景

| 用户角色 | 典型场景 |
| --- | --- |
| 个人量化爱好者 | 每日盘后更新行情，运行多因子打分，查看当日选股榜单 |
| 量化研究员 | 研究新因子（如动量、波动率、价值），做因子 IC/分层测试 |
| 策略开发者 | 将因子组合成选股策略，在历史区间回测，评估收益回撤 |
| 模拟交易者 | 按选股信号在模拟账户中买卖，跟踪策略的实盘模拟表现 |

## 2. 系统总体架构

### 2.1 架构分层

系统采用分层架构，自下而上分为四层：数据层、引擎层、业务层、接口层。

```
┌──────────────────────────────────────────────────────────────┐
│                        接口层 (Interface)                      │
│        CLI 命令行  │  Python SDK  │  (预留) Web/REST API        │
├──────────────────────────────────────────────────────────────┤
│                       业务层 (Application)                     │
│  选股任务  │  定时调度(盘后更新)  │  报告/报表导出  │  策略管理    │
├──────────────────────────────────────────────────────────────┤
│                         引擎层 (Engine)                        │
│  多因子分析引擎   │   模拟持仓管理   │      回测引擎             │
├──────────────────────────────────────────────────────────────┤
│                         数据层 (Data)                          │
│          行情数据获取代理（多源轮换 + 本地缓存）                 │
│   数据源A(Tushare)  数据源B(AKShare)  数据源C(东财/新浪...)      │
├──────────────────────────────────────────────────────────────┤
│  本地存储: Parquet 文件(行情)  │  SQLite/ DuckDB (元数据/交易)   │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 模块总览

| 模块 | 核心职责 | 关键产出 |
| --- | --- | --- |
| 行情数据获取代理 | 多源接入、故障轮换、本地缓存、数据标准化 | 统一口径的行情数据集 |
| 多因子量化分析引擎 | 因子定义/计算/预处理/打分/有效性检验 | 因子值、综合得分、选股列表 |
| 模拟持仓管理 | 模拟账户、委托成交、持仓资金、对账 | 资金流水、持仓、盈亏 |
| 回测引擎 | 历史回放、信号撮合、绩效统计 | 回测报告（收益/风险/换手） |

### 2.3 核心数据流

1. **盘后数据更新流**：调度器 → 数据代理（缓存未命中）→ 轮换数据源拉取 → 标准化校验 → 写入本地缓存（历史数据永久化）。
2. **选股研究流**：数据代理读取本地行情 → 因子引擎计算因子值 → 预处理（去极值/标准化/中性化）→ 加权合成综合得分 → 输出 Top N 选股榜。
3. **模拟交易流**：选股信号 → 模拟账户下单 → 撮合（按次日开盘价等规则）→ 更新持仓与资金 → 每日盯市盈亏。
4. **回测验证流**：设定股票池/区间/策略 → 回测引擎按交易日逐 bar 回放 → 调用因子引擎生成信号 → 模拟账户撮合 → 绩效指标与报告。

## 3. 功能需求详细设计

## 3.1 行情数据获取代理（Market Data Proxy）

### 3.1.1 功能概述

数据代理是系统唯一的行情数据出口，对上屏蔽多数据源差异，对下统一管理缓存与数据源生命周期。核心能力：**多源接入、自动轮换、分层缓存、数据标准化、质量校验**。

### 3.1.2 数据源管理

**（1）数据源抽象接口**

所有数据源实现统一适配器接口（Adapter Pattern），保证可插拔：

```python
class MarketDataSource(ABC):
    name: str                          # 数据源标识，如 tushare / akshare / eastmoney
    priority: int                      # 调用优先级（数字越小越优先）
    rate_limit: RateLimitSpec          # 限频规格（QPS/日积分额度）

    def fetch_daily_bars(self, symbol, start, end, adjust) -> pd.DataFrame: ...
    def fetch_realtime_quote(self, symbols) -> pd.DataFrame: ...
    def fetch_stock_list(self, market) -> list[Instrument]: ...   # 股票列表/上市退市
    def fetch_calendar(self, market) -> list[date]: ...           # 交易日历
    def health_check(self) -> bool: ...                           # 可用性探测
```

**（2）v1.0 计划接入数据源**

| 数据源 | 接入内容 | 优先级建议 | 备注 |
| --- | --- | --- | --- |
| Tushare Pro | 日线、复权因子、股票列表、交易日历 | 1（配置 token 后） | 字段规范、积分限频 |
| AKShare | 日线、实时行情、股票列表 | 2 | 免费、依赖网页接口，稳定性一般 |
| 东方财富/新浪 | 日线、实时行情 | 3 | 作为兜底源 |

> 数据源通过配置文件注册，支持启用/禁用、调整优先级、配置密钥与限频参数，新增数据源无需改动上层代码。

### 3.1.3 故障自动轮换机制

**（1）轮换触发条件**

- 网络异常：连接超时、DNS 失败、HTTP 5xx。
- 业务异常：鉴权失败（token 失效/积分不足）、接口返回错误码。
- 数据异常：返回空数据、字段缺失、行数明显不符（非停牌原因）、数据校验未通过。
- 限频异常：触发 QPS/日配额限制。

**（2）轮换策略**

1. 按数据源 `priority` 升序依次尝试；同一数据源在指数退避下最多重试 N 次（默认 2 次，间隔 1s/2s/4s）。
2. 当前源失败后，**自动切换到下一优先级数据源**，直至成功或全部源耗尽。
3. 全部失败时抛出聚合异常 `AllSourcesExhaustedError`，记录失败上下文并支持断点续传（下次只拉缺失部分）。
4. **熔断器（Circuit Breaker）**：某数据源在滑动窗口（如 10 分钟）内连续失败达阈值（如 5 次），自动熔断冷却（如 5 分钟），期间直接跳过，冷却后半开探测。
5. 每次轮换记录结构化日志（请求参数、失败源、失败原因、耗时、最终命中源），便于排查数据源质量。

**（3）请求去重与限频**

- 每个数据源独立限频器（令牌桶），遵守其 QPS 与日配额。
- 相同参数的并发请求合并（SingleFlight），避免缓存击穿。

### 3.1.4 本地缓存设计（重点）

**（1）数据冷热分级**

| 数据分类 | 可变性 | 缓存策略 | 示例 |
| --- | --- | --- | --- |
| **已收盘历史 K 线** | 永久不变（除复权因子回溯） | **永久保存，不再重复请求** | 2026-09-09 及之前的日线 |
| 当日未收盘行情 | 盘中实时变化 | 短 TTL（如盘中 15s）或不缓存 | 实时分时、最新价 |
| 当日收盘后数据 | 收盘后短期可能被源修正 | 收盘后 T+1 日内允许刷新 1 次，之后固化 | 当日日线 |
| 基础数据 | 低频变更 | 长 TTL + 手动/定时刷新 | 股票列表、交易日历、复权因子 |

**（2）"历史数据永久保存"的判定规则**

- 以交易日历为基准：对任意 `trade_date < 今日（且已过收盘时刻）` 的 K 线，视为**封闭数据（Closed Bar）**。
- 封闭数据写入本地后标记 `is_final = true`，后续请求**命中缓存即直接返回，不再发起网络请求**。
- 例外处理：复权因子可能因新分红送转而导致**前复权价格**整体变化。因此：
  - 本地**永久保存原始价（不复权 OHLCV）与复权因子**两份数据；
  - 前/后复权视图在读取时按最新复权因子动态计算；
  - 复权因子表低频增量更新（如每周或检测到除权除息事件时）。

**（3）存储方案**

| 存储 | 用途 | 选型理由 |
| --- | --- | --- |
| Parquet 文件（按代码+年份分区） | 日线等大规模行情 | 列存压缩、按分区裁剪、pandas/Arrow 读取快 |
| SQLite / DuckDB | 缓存元数据、股票列表、交易日历、数据血缘 | 单文件、零运维、便于索引与去重 |
| 内存缓存（LRU） | 当日热点数据、实时行情 | 降低盘内重复计算 IO |

目录结构示例：

```
data/
├── market/
│   ├── daily/
│   │   └── 000001.SZ/
│   │       ├── 2024.parquet      # 按代码+年分区，封闭数据永久保存
│   │       └── 2025.parquet
│   ├── adjust/                   # 复权因子
│   └── instruments/              # 证券主数据
├── meta.db                       # SQLite：缓存索引、数据血缘、数据源状态
└── trading/                      # 模拟交易与回测结果（见后续章节）
```

**（4）缓存读写流程**

```
请求行情(symbol, start, end, adjust)
        │
        ▼
 查询缓存索引，计算 [start,end] 区间覆盖情况
        │
        ├── 区间已全部封闭且本地完整 ──► 直接读本地（不联网）
        ├── 部分缺失 ──► 仅向数据源请求"缺失区间"（增量拉取）
        └── 含当日实时数据 ──► 历史段读本地 + 当日段走实时源(TTL)
        │
        ▼
 标准化 + 质量校验 ──► 写回缓存（封闭数据置 is_final=true）
```

- **增量更新**：缓存索引记录每个 symbol 的 `last_trade_date`，更新时自动以其为起点向后拉取，避免全量重取。
- **缓存修复**：提供 `repair` 命令，可按区间/股票强制重拉，用于源数据事后修正。

### 3.1.5 数据标准化与质量校验

**（1）统一数据模型**：不同源字段映射为内部标准字段，证券代码统一为 `代码.交易所` 格式（如 `600519.SH`），时间统一时区与交易日口径，价格统一单位，复权方式统一枚举（`none/qfq/hfq`）。

标准日线字段：`symbol, trade_date, open, high, low, close, volume, amount, turnover, pre_close, adj_factor(可选)`。

**（2）质量校验规则**

| 校验类型 | 规则示例 |
| --- | --- |
| 完整性 | 交易日非停牌日必须有记录；关键字段非空 |
| 合法性 | high ≥ max(open,close) ≥ min(open,close) ≥ low；价格/成交量 > 0 |
| 连续性 | 与前收盘价差异超过阈值（如 22%，A股涨跌停）标记疑似异常 |
| 一致性 | 多数据源对同一封闭日期交叉抽检（可选开关） |
| 停牌处理 | 成交量为 0 且价格不动时正确标记停牌，不视为数据缺失 |

校验失败的数据进入隔离区（quarantine）并告警，不污染正式缓存。

## 3.2 多因子量化分析引擎（Factor Engine）

### 3.2.1 功能概述

提供从因子定义、批量计算、预处理、合成打分到有效性检验的完整研究链路，所有计算基于数据代理提供的统一行情，保证研究口径一致、可复现。

### 3.2.2 因子框架设计

**（1）因子分层**

| 层级 | 说明 | v1.0 内置示例 |
| --- | --- | --- |
| 价量因子 | 基于 OHLCV 计算 | 动量（20日/60日收益率）、反转、波动率、换手率、振幅 |
| 技术指标因子 | 常用技术指标 | RSI、MACD、布林带位置、均线乖离 |
| 规模/流动性因子 | 市值、成交额 | 总市值（需市值数据）、日均成交额 |
| 基本面因子（预留） | 估值/财务 | PE/PB/ROE（v1.x 接入财务数据源后启用） |

**（2）因子定义接口（声明式 + 代码式）**

```python
class Factor(ABC):
    name: str
    window: int | None
    dependencies: list[str]          # 依赖的行情字段/其他因子

    @abstractmethod
    def compute(self, data: PanelData) -> pd.DataFrame: ...   # 返回 index=日期, columns=股票
```

示例（20 日反转因子）：

```python
class Reversal20(Factor):
    name = "rev_20"
    dependencies = ["close"]
    def compute(self, data):
        return -data.close.pct_change(20)
```

引擎支持通过 YAML 注册内置因子与自定义权重，无需改引擎代码即可组合。

### 3.2.3 因子计算调度

- **面板数据（Panel）计算**：以"日期 × 股票"二维面板为输入，向量化计算，避免逐股票循环。
- **增量计算与缓存**：因子值按 `因子名 + 参数 + 数据版本（复权方式/更新日期）` 缓存；行情更新后仅重算受影响窗口，复用历史结果。
- **幸存者偏差控制**：股票池支持纳入当时已退市股票（point-in-time 成分），避免只用当前在市股票导致的前视偏差。

### 3.2.4 因子预处理流水线

每个截面（每个交易日横截面上）依次执行，步骤可配置开关：

1. **缺失值处理**：剔除覆盖率不足的股票，或使用行业/截面中位数填充。
2. **去极值**：MAD（中位数绝对偏差）法或 3σ 缩尾（Winsorize）。
3. **标准化**：Z-Score 标准化（截面均值为 0、标准差为 1）。
4. **中性化（可选）**：对行业哑变量、市值对数做回归取残差，剔除行业/风格暴露。
5. **方向统一**：将因子方向统一为"值越大越看多"。

### 3.2.5 因子合成与选股打分

- 支持加权合成：`综合得分 = Σ(权重_i × 标准化因子_i)`，权重支持等权、人工设定、IC 加权、IC_IR 加权。
- 输出：每个交易日每只股票的单因子值、综合得分、排名与分位分组。
- 选股规则可配置：`Top N`、`前 X%`、`得分阈值`、行业/单票上限、剔除停牌/ST/次新/涨跌停不可成交股票。
- 产出**每日选股榜单**，供模拟交易与报告使用。

### 3.2.6 因子有效性检验

| 检验方法 | 指标 | 含义 |
| --- | --- | --- |
| IC 分析 | Pearson/Spearman IC、IC 均值、ICIR、IC 胜率 | 因子值与未来收益的预测相关性 |
| 分层回测 | 5/10 分组收益、多空组合收益、单调性 | 因子区分度 |
| 收益分析 | 因子各分位年化收益、夏普 | 经济性 |
| 换手与相关性 | 因子自相关/换手率、因子间相关系数矩阵 | 因子独立性、交易成本敏感度 |

### 3.2.7 业务规则与异常

- 新股上市未满 N 个交易日不参与因子计算（窗口不足）。
- 停牌日沿用上一可得因子值并打标记；复牌后重新计算。
- 因子计算全程记录数据版本、参数、随机处理（如有），保证结果可复现。

## 3.3 模拟持仓管理（Paper Portfolio）

### 3.3.1 功能概述

提供一个贴近真实 A 股交易规则的模拟账户体系，管理资金、委托、成交、持仓与盈亏，既可用于盘后纸上交易，也作为回测引擎的底层账户组件。

### 3.3.2 账户与资金模型

- 支持多账户：每个策略/用户可创建独立模拟账户，初始资金可设定（默认 1,000,000）。
- 资金账户字段：`可用资金、冻结资金、持仓市值、总资产、累计盈亏、当日盈亏`。
- 资金流水：出入金、买入冻结、卖出回款、手续费、印花税、过户费均留痕，支持对账。

### 3.3.3 交易规则（A 股）

| 规则项 | v1.0 设定（可配置） |
| --- | --- |
| 交易单位 | 买入 100 股整数倍，卖出可零股（清仓时） |
| 交易制度 | T+1（当日买入次日方可卖出） |
| 涨跌幅限制 | 下单价格不得超出涨跌停价；主板 ±10%、创业板/科创板 ±20% |
| 撮合价格 | 模拟默认按下一个交易日开盘价成交（防未来函数），可选当日收盘/VWAP |
| 成交约束 | 跌停无法买入、涨停无法卖出、停牌不可交易、一字板无法成交 |
| 交易成本 | 佣金（默认万 2.5，最低 5 元）、印花税（卖出千 1）、过户费（可选） |
| 滑点 | 固定比例（如万 5）或固定跳数，可开关 |

### 3.3.4 委托与成交状态机

```
新建(NEW) ──提交──► 待报(PENDING) ──撮合──► 部分成交(PARTIALLY_FILLED) ──┐
   │                   │                              │                  │
   │                   ├──拒绝──► 已拒绝(REJECTED)     └──────────────► 全部成交(FILLED)
   └──撤单──► 已撤单(CANCELLED)      └──撤单──► 已撤单(未成交部分)
```

- 订单字段：`账户、股票、方向(买/卖)、订单类型(市价/限价)、委托量价、时间、状态、成交均价、手续费`。
- 模拟模式下提供"信号即委托"的快捷接口（由选股结果一键生成目标调仓订单）。

### 3.3.5 持仓与盯市

- 持仓字段：`股票、持仓量、可用量（T+1 冻结）、成本价、最新价、市值、浮动盈亏、累计盈亏`。
- 每日盘后用数据代理的当日收盘价进行盯市（Mark-to-Market），刷新净值。
- 支持公司行为占位：除权除息时按复权因子调整持仓数量/成本（v1.0 简化处理，详细分红再投资列入 v1.x）。

### 3.3.6 调仓与目标持仓

- 支持**目标持仓调仓**：输入"目标股票+目标权重/股数"，系统自动计算买卖差价单（rebalance order）。
- 调仓约束：最大持仓数、单票权重上限、行业集中度、换手率上限。
- 每日生成调仓清单、预计成交额与费用，确认后写入订单。

### 3.3.7 盈亏与报表

- 账户净值曲线、日/累计收益率、胜率、平均持仓天数、换手率。
- 持仓明细、资金流水、成交流水可导出 CSV/Excel。

## 3.4 回测引擎（Backtest Engine）

### 3.4.1 功能概述

在历史数据上还原策略运行过程，严格防止未来函数与幸存者偏差，输出可信赖的绩效评估。回测引擎复用 3.2 因子引擎生成信号、复用 3.3 模拟账户进行撮合与记账。

### 3.4.2 引擎范式

- **事件驱动（Event-Driven）**主循环，按交易日逐 bar 推进，核心事件：`市场事件(新Bar) → 信号事件 → 订单事件 → 成交事件 → 收盘盯市事件`。
- v1.0 以**日线频率**为主，架构上预留分钟 bar 的事件扩展点。

### 3.4.3 策略接口

```python
class Strategy(ABC):
    def on_start(self, ctx): ...                 # 初始化：设置股票池、调仓频率
    def on_bar(self, ctx, bar_date):             # 每个交易日触发
        signals = ctx.factors.score(bar_date)    # 仅使用 <= bar_date 可见数据
        target  = ctx.select(signals, top_n=20)
        ctx.rebalance(target)                    # 生成目标调仓订单
    def on_end(self, ctx): ...
```

- **防未来函数**：`on_bar(date)` 内只能访问 `≤ date` 的数据；因子引擎对标签和收益严格右对齐；默认信号次日成交。
- **Point-in-time 股票池**：使用当时实际在市、当时的指数成分（若接入），退市股保留在历史中。

### 3.4.4 回测配置项

| 配置 | 说明 | 默认值 |
| --- | --- | --- |
| 回测区间 | 起止日期 | 必填 |
| 初始资金 | 模拟账户本金 | 1,000,000 |
| 基准指数 | 用于相对收益评估 | 沪深300（000300.SH） |
| 股票池 | 全 A / 指数成分 / 自定义列表 | 全 A（剔除 ST、上市未满 60 日） |
| 调仓频率 | 每日/每周/每月 | 每月（最后交易日） |
| 选股数量 | 持仓只数 | 20 |
| 加权方式 | 等权/得分加权 | 等权 |
| 交易成本 | 佣金/印花税/滑点 | 见 3.3.3 |
| 涨跌停/停牌成交 | 是否严格限制 | 严格限制 |

### 3.4.5 撮合与成交模型（日线）

- T 日收盘后产生信号 → T+1 日按**开盘价**（或 VWAP/收盘价，可配）成交。
- 开盘涨停买单、开盘跌停卖单、停牌单：默认拒单或顺延 N 日（可配）。
- 成交量约束（可配高级项）：单笔成交量不超过该 bar 成交量的一定比例（如 10%），模拟市场冲击。
- 现金不足自动按可得资金缩减买单；T+1 校验卖出可用数量。

### 3.4.6 绩效指标体系

| 类别 | 指标 |
| --- | --- |
| 收益 | 累计收益、年化收益、超额收益（相对基准）、净值曲线 |
| 风险 | 年化波动率、最大回撤、最大回撤持续期、下行波动率 |
| 风险调整收益 | 夏普比率、索提诺比率、卡玛比率、信息比率、特雷诺比率 |
| 交易统计 | 总换手、日均换手、胜率、盈亏比、平均持仓天数、交易笔数、总费用 |
| 归因（基础） | 相对基准超额、行业暴露、（v1.x）Brinson 归因 |

### 3.4.7 回测报告

- 输出结构化回测结果对象，并生成 HTML/Markdown 报告，包含：
  - 净值曲线 vs 基准曲线、回撤曲线；
  - 月度/年度收益热力图；
  - 绩效指标表、滚动指标（滚动夏普/滚动 IC）；
  - 持仓与交易明细、换手率序列；
  - 回测配置快照与数据版本（保证可复现）。
- 同一策略支持多组参数批量回测，结果落库可横向对比。

### 3.4.8 回测准确性约束

- 单一时间轴推进，禁止向前/向后"偷看"数据。
- 所有价格、成分、复权口径以历史时点可得信息为准。
- 明确区分"信号日、委托日、成交日"，并在报告中披露撮合假设与成本假设。

## 3.5 Web 管理后台（Web Console）

### 3.5.1 功能概述

Web 管理后台是系统面向用户的主要可视化入口，将数据代理、因子引擎、模拟持仓、回测引擎四大能力通过浏览器统一呈现与操作，使不写代码的用户也能完成"数据更新 → 因子研究 → 选股 → 模拟交易 → 回测验证"的全流程。

- **部署形态**：随系统本地部署，后端内嵌 Web 服务器（默认访问地址 `http://127.0.0.1:xxxx`），前端单页应用（SPA）的构建产物由后端托管，执行 `conflex web start` 一键启动，无需额外安装数据库或中间件。
- **架构形态**：前后端分离，链路为"浏览器 ⇄ REST API ⇄ 业务层/引擎层"；CLI、SDK 与 Web 共用同一套引擎内核，保证三种入口的结果口径完全一致。
- **设计原则**：只读信息丰富、写操作有确认、长任务有进度、危险操作有审计。

### 3.5.2 用户、登录与权限

- v1.0 为**单用户本地模式**：首次启动引导创建管理员账号（用户名 + 密码），支持退出登录与修改密码；密码加盐哈希存储，不提供公开注册入口。
- 预留两类角色：
  - **管理员（Admin）**：全部功能，含数据源配置、数据修复、任务管理、模拟下单/撤单、全局参数设置；
  - **观察者（Viewer，预留）**：仅可查看行情、因子、持仓与回测报告，不可触发任何写操作。
- 鉴权方式：登录成功后下发签名 Token（JWT/Session），除登录接口外的 API 均需认证。
- 安全交互：数据源 Token 等密钥录入后脱敏显示（仅展示后 4 位）；数据修复、撤单、删除记录等危险操作需二次确认。
- 所有写操作记录操作人、时间、对象与内容，形成操作审计日志。

### 3.5.4 异步任务与实时反馈

- 数据更新、全市场因子计算、回测等耗时操作统一抽象为**异步任务（Job）**：前端提交后立即返回任务 ID，任务在后台工作线程执行，页面不阻塞。
- 任务状态机：`排队 QUEUED → 运行 RUNNING（携带 progress 百分比与阶段信息）→ 成功 SUCCEEDED / 失败 FAILED（可重试）/ 已取消 CANCELLED`。
- 前端通过 **SSE（Server-Sent Events）** 或轮询订阅任务进度与日志流；页面关闭后重新打开仍可看到任务最新状态；任务完成后在导航栏推送通知。
- 本地单机模式采用进程内任务管理器，串行或有限并行执行，避免并发触发数据源限频；接口预留未来切换 Celery/RQ 等分布式队列的扩展点。

### 3.5.5 REST API 设计

- 统一前缀 `/api/v1`，使用 JSON、RESTful 风格，自动生成 OpenAPI/Swagger 在线文档（`/api/docs`）。
- 主要资源与典型接口：

| 资源 | 典型接口 |
| --- | --- |
| 认证 | `POST /auth/login`、`POST /auth/logout`、`PUT /auth/password` |
| 数据源 | `GET/PUT /data-sources`、`POST /data-sources/{name}/test` |
| 任务 | `POST /data/jobs`、`GET /jobs`、`GET /jobs/{id}`、`GET /jobs/{id}/logs`、`POST /jobs/{id}/cancel` |
| 行情与缓存 | `GET /market/bars`、`GET /cache/coverage`、`POST /cache/repair` |
| 因子 | `GET /factors`、`POST /factors/compute`、`GET /factors/{name}/analysis` |
| 选股与策略 | `GET /scores`、`GET/POST/PUT/DELETE /strategies` |
| 模拟交易 | `GET/POST /accounts`、`GET /positions`、`GET /cash-flows`、`POST /orders`、`DELETE /orders/{id}` |
| 回测 | `POST /backtests`、`GET /backtests`、`GET /backtests/{id}/report` |
| 系统 | `GET/PUT /settings`、`GET /operation-logs` |

- 同一套 API 同时服务 Web 前端与外部脚本（支持 API Key 调用）；CLI 可走该 API，也可直接调用引擎内核。
- 列表查询统一支持分页（`page/page_size`）、排序与条件筛选；错误响应使用统一错误码与可读提示。

### 3.5.6 前端可视化与交互要求

- **图表能力**：K 线（叠加成交量）、净值/基准对比、回撤曲线、分层收益、IC 时序、月度收益热力图、因子相关性热力图；支持缩放、十字光标、图例切换、图片与底层数据导出。
- **数据表格**：服务端分页、列排序、条件筛选、固定表头、金额/百分比格式化、CSV/Excel 导出。
- **表单与校验**：策略编辑与回测配置采用向导式表单 + 前后端双重校验；危险操作二次确认弹窗。
- **体验要求**：PC 优先（适配 1280px 以上宽度），中文界面（预留 i18n 结构）；加载中、空数据、请求错误三态完备；全局消息提示与任务通知中心。

### 3.5.7 安全与部署边界

- 服务默认仅绑定回环地址 `127.0.0.1`，不对局域网/公网暴露；如需内网访问，须由用户显式修改监听地址，建议自行配合反向代理与 HTTPS。

## 4. 数据模型概要

Job(异步任务: 数据更新/因子计算/回测)
DataSourceStat(数据源状态/熔断/调用统计)

## 5. 接口与使用方式

系统提供三种使用方式：**Web 管理后台**（主要交互入口）、**CLI**（运维与脚本化）与 **Python SDK**（研究扩展），三者共用同一套引擎内核，Web 前端通过 REST API 访问：

```bash
# 启动 Web 管理后台（默认 http://127.0.0.1:8899，首次启动引导创建管理员账号）
conflex web start --host 127.0.0.1 --port 8899

# 数据：初始化/增量更新/修复
conflex data update --freq daily --end today
conflex data repair --symbol 600519.SH --start 2025-01-01

# 因子：计算单因子并查看 IC
conflex factor run rev_20 --ic

# 选股：生成当日 Top20 榜单
conflex select --strategy momentum_reversal --top 20

# 模拟交易：按榜单调仓并查看持仓
conflex paper rebalance --account demo --strategy momentum_reversal
conflex paper positions --account demo

# 回测
conflex backtest run --strategy momentum_reversal \
    --start 2021-01-01 --end 2026-08-31 --benchmark 000300.SH --report html
```

```python
# SDK 用法示意
from conflex import data, factors, backtest

df = data.get_daily("600519.SH", "2024-01-01", "2026-09-10", adjust="qfq")
result = backtest.run(MyStrategy(), start="2021-01-01", end="2026-08-31",
                      benchmark="000300.SH", initial_cash=1_000_000)
print(result.metrics.sharpe, result.metrics.max_drawdown)
```

| 部署 | 纯本地运行，pip 安装（`pip install conflex[web]`），`conflex web start` 一键启动；零外部中间件依赖（数据源 API 除外）；配置文件化管理 token |
| 安全 | 数据源密钥仅存本地配置（支持环境变量注入），不上传任何数据；Web 默认仅绑定 127.0.0.1，登录鉴权、密钥脱敏、CSRF 防护、危险操作二次确认与操作审计 |
| 浏览器兼容 | 支持 Chrome/Edge/Firefox/Safari 最近两个大版本；PC 端 1280px 以上宽度优先适配 |
| 任务并发 | 数据更新/全量因子计算/回测等长操作异步化，页面不阻塞；任务进度实时推送、失败可重试，任务持久化后重启不丢失 |

## 7. 技术选型建议

| 领域 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.10+ | 量化生态成熟、研究友好 |
| 数据处理 | pandas + NumPy + PyArrow | 面板/向量化计算、Parquet 读写 |
| 行情源 | Tushare、AKShare、自建东财/新浪适配器 | 覆盖免费与稳定源 |
| 行情存储 | Parquet（分区文件） | 列存、高压缩、分区裁剪 |
| 元数据/交易库 | SQLite（默认）/ DuckDB（分析加速，可选） | 零运维、单文件 |
| 回测 | 自研事件驱动内核 | 与因子/模拟账户深度复用、口径统一 |
| Web 后端 | FastAPI + Uvicorn（REST API） | 原生异步、自动生成 OpenAPI 文档、与 pandas 生态契合 |
| Web 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router | 组件丰富、生态成熟，适合数据密集型管理后台 |
| 前端图表 | ECharts（K 线/净值/热力图） | 金融图表能力强、交互与大数据量渲染性能好 |
| 鉴权 | JWT（python-jose）+ passlib/bcrypt | 无状态 Token、密码加盐哈希 |
| 异步任务 | 进程内任务管理器（ThreadPool/进程池）+ SSE 进度推送 | 本地零中间件；预留 Celery/RQ 切换扩展点 |
| 报告 | Jinja2 + Plotly/Matplotlib | HTML 交互图表报告（后台报告页与离线导出共用） |
| 调度 | APScheduler（盘后定时任务） | 轻量本地调度，与任务管理器复用 |
| 测试 | pytest + 黄金样本数据集 + 前端组件测试 | 因子/撮合/防未来函数回归测试、API 契约测试 |

> 说明：优先自研轻量内核以保证四模块数据口径完全一致；后续若性能需要，可评估集成 vectorbt/backtrader 作为加速后端，但对上层接口保持不变。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 免费数据源接口频繁变更/封禁 | 数据中断 | 多源热备 + 适配器隔离变更；熔断与告警；本地永久缓存降低对源的依赖 |
| 复权导致历史价变化 | 因子/回测结果漂移 | 原始价与复权因子分离存储，复权视图动态计算 |
| 未来函数/幸存者偏差 | 回测虚高、结论失真 | Point-in-time 股票池、信号次日成交、统一时间轴、专项单测与代码审查 |
| 回测过拟合 | 策略实盘失效 | 披露样本内外、参数稳健性测试、交易成本与冲击充分计提 |
| 单机性能瓶颈 | 全市场长区间计算慢 | Parquet 分区裁剪、因子增量缓存、向量化；必要时引入 DuckDB/多进程 |
| Web 服务暴露导致未授权访问或密钥泄露 | 数据被拉取、模拟账户被误操作 | 默认仅绑定 127.0.0.1、强制登录鉴权、密钥脱敏、危险操作二次确认、操作审计；内网开放须显式配置并建议反代+HTTPS |
| 长任务阻塞或进度不可见 | 用户重复提交、误以为系统卡死 | 统一异步任务模型、SSE 实时进度与日志、任务排队/取消/重试、任务状态持久化 |

## 10. 附录：术语表

| 术语 | 说明 |
| --- | --- |
| Bar / K 线 | 固定周期的 OHLCV 行情单元，v1.0 主要指日线 |
| 封闭数据（Closed Bar） | 已收盘且不会再变更的历史行情，永久缓存 |
| 复权因子 | 处理分红送转、使价格序列连续的调整系数 |
| IC / ICIR | 信息系数 / IC 均值与标准差之比，衡量因子预测力与稳定性 |
| Point-in-time | 严格使用历史时点可得信息，避免前视偏差 |
| Paper Trading | 模拟交易 / 纸上交易，不涉及真实资金 |
| 熔断（Circuit Breaker） | 数据源连续失败后暂时跳过的保护机制 |
| SPA | 单页应用（Single Page Application），Web 后台前端形态 |
| 异步任务（Job） | 数据更新、因子全量计算、回测等长耗时操作，后台执行并可查询进度 |
| SSE | Server-Sent Events，服务端向前端单向推送任务进度与日志的机制 |
